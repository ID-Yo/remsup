# Read-only runtime diagnostics

An authenticated operator may send `REMSUPDIAG1` on the existing COMMAND channel. It occupies the same bounded command gate, then releases/re-registers it; SCREEN remains independent. No command executor, support start, update check, settings/firewall mutation or UAC action is invoked. Stop/suspension/disconnect keep their existing behavior. Diagnostic reads require the exact device credentials and caller's authorized task scope.

Modern receivers return `REMSUPDIAG1 <base64 UTF-8 JSON>`, at most 16 KiB decoded. Schema version 1 includes normalized running version; LAN configured/enabled/ready and an allowlisted warning; relay state/ready; automatic updates enabled; last completed check UTC/result/version/error code; last verified download UTC/version/SHA256; last install UTC/result/error code; and at most eight sanitized recent error codes. No device identity, address, password, OTP, token, certificate/private key, command/output, screen content or arbitrary exception text is returned. Unknown warning text becomes `LAN diagnostics unavailable.`

The MCP tool `remsup_diagnostics(device_id, otp)` authenticates its bearer caller, uses one COMMAND pairing, validates/projects the schema and audits only hashed caller, result code and duration. It has no automatic replay, shell fallback or screen-session side effects. Older clients return `unsupported`; missing provider returns `unavailable`; denied/busy/transport failures are safe controlled states. No server restart or deployment is implied by source availability.

Local diagnostics live in `%LOCALAPPDATA%/Remsup/logs`: `state.jsonl` rotates at 256 KiB to one prior log; `update-summary.json` retains only fixed latest records and eight codes. Reads never force a network update. Existing bounded v1.48 last-check events are imported when no new summary exists; install/rollback history cannot be inferred from a download cache. Corrupt/unavailable files leave unknown fields; diagnostics are best effort and do not change support availability.

Settings > General displays the persistent UTC timestamp, check result/version and last install/rollback code. Disabled updates are shown separately from historical completed checks. Current/Available/Error, verified download, Deferred/Installed/RolledBack/RecoveryFailed/Failed records are distinct. An accepted install outcome is persisted before predecessor exit, and candidates reload the shared summary for subsequent display. Active-support consent and readiness/rollback gates remain unchanged.

Local owned fixtures verify actual ten-second LAN watcher recovery, Stop/update suspension, authenticated diagnostic wire, schema/credential safety, persistent reopen/readiness/rollback, and rendered Settings visibility. They do not prove a customer upgrade or deployed MCP tool.
